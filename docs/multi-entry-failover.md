# 多入口主备与固定出口

在「链式代理 → 多入口负载均衡 · 主备切换」新增主备组，选择 2–8 个入口，按主用到备用排列，再选择一个固定出口。所有入口和出口必须是不同的、已登记到总控的服务器；节点凭据也须匹配服务器中的真实入站。未登记的节点会提示改用 Mihomo 客户端专用链式代理模式。

面板在每个入口新建专属 Reality 转发入站，将其出站都指向同一出口节点，不改动原入站。当前界面为每台入口使用相同的新端口；请确保该端口未占用并已在防火墙开放，填写各入口均能访问的 Reality SNI。每个新入站自动归属当前订阅，沿用总流量计量、到期撤销与失败重试。

生成的 Mihomo `fallback` 组仅包含这些转发路径。默认每 30 秒主动检测完整链路（`lazy: false`，超时 5 秒），优先选择第一个可用入口；主入口恢复后，新连接自动切回。可配置 10–600 秒检测间隔。切换时间受检测周期和超时影响，已有 TCP 会话可能需要重连。检测地址为 `https://www.gstatic.com/generate_204`，请确认出口能够访问此地址。

Mihomo 客户端需更新完整 Clash/Mihomo 订阅，并在业务策略组中选中此主备组。电脑 v2rayN、安卓 v2rayNG 的 Xray 主备配置以及 iPhone Shadowrocket 的配对节点/策略导入见 [客户端适配说明](client-compatibility.md)。单节点 URI 和普通节点订阅格式不能表达组级自动切换；本功能也不提供跨服务器漂移的统一入口 IP。页面状态表示配置结果，不表示在线客户端的即时健康状态。

所有入口都使用同一出口凭据，不自动改用其他出口或 DIRECT。全部入口不可用时连接失败；出口本身故障时也无法连接。公网出口 IP 是否始终相同还取决于出口服务器的静态地址、IPv4/IPv6 和 NAT 设置，应在真实客户端验证。

自动生成的路径和主备组受编辑/删除保护，普通新增节点不会加入这些专用 fallback 组。需要更换顺序或出口时删除整组后重建。删除先将该组的引用改为 REJECT，再清理专属远端入站，避免清理途中空组退回直连。远端清理失败会保留错误和待清理路径，可重试删除；创建中途失败会尝试撤回已创建的路径。无法访问的服务器应恢复连接后再清理。

本地验证覆盖固定出口参数、优先顺序、订阅归属及过期撤销、编辑保护、创建失败回滚、删除失败重试、并发节点保存。可选真实 Mihomo 测试使用两个本地入口代理和一个共同出口，验证主入口 → 备用入口 → 主入口，以及全部入口失效时连接失败：

```sh
MXIOC_MIHOMO_BIN=/path/to/mihomo python -m unittest discover -s tests -p test_mihomo_failover.py -v
```

该测试不接入生产服务器，不验证实际服务器 SSH、防火墙、公网出口 IP 或 Reality 握手。
