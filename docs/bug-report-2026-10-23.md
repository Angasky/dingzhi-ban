# 全流程测试与 BUG 修复报告

> 此文件为上传修复包附带的原始验证记录。文中的环境、耗时与“181 项无跳过”来自归档，不表示本次发布在 Windows 上重新完成了全部 Linux / 原生内核测试；本次发布检查见仓库 CHANGELOG.md。文中“尚未推送”为报告生成时状态，非当前仓库状态。

测试日期：2026-10-23（UTC）。结论：复现并修复 **7 个 BUG**，完成 **1 项连接开销优化**。本报告针对当前本地工作区，修改尚未推送 GitHub 或部署到 vpn.mxvv.cn。

## 环境与测试边界

使用 Python 3.12.14、Node.js 24.19.0、Chromium、Xray 26.10.21、sing-box 1.14.3、Mihomo 1.19.33，以及 nftables 1.0.6。数据位于临时目录；代理和管理 HTTP 服务只监听本机，nftables 测试使用隔离用户 / 网络命名空间，不修改宿主防火墙。

HTTP 流程使用真实处理器、Cookie 登录、配置读写和业务逻辑；远端 SSH / 面板传输使用测试替身。另有本地真实 SSH 握手、面板 HTTP 适配、内核配置验证、主备流量和内核限速测试，分别验证相应环节。不能将这些分层测试等同于已经在用户的完整生产环境上线验收。

## 已复现并修复的问题

P1 为影响计费、撤销或限速正确性的问题；P2 为异常处理与操作可靠性问题。本报告分级表示产品影响，不是外部漏洞评级。

| 编号 | 级别 | 复现步骤与修复前结果 | 修复方法与回归结果 |
| --- | --- | --- | --- |
| BUG-01 | P1 | 设置订阅到期，远端节点删除成功，但 `ss` 存量连接清理连续失败。第二轮扫描发现入站消失后，将绑定标记为 missing，后续不再重试连接清理。 | 清理失败保留 active 待重试状态。回归模拟连续失败两次、第三次成功，确认清理调用 3 次，最终 revoked。 |
| BUG-02 | P1 | 给 VLESS TCP 节点限速，再编辑相同入站，将底层传输改为 KCP / UDP。协议名、端口均没变，旧 TCP 限速规则无法约束新 UDP 流量。 | 比较限速策略需要的 TCP / UDP 协议集合；切换前必须取消限速。回归确认变更被拒绝，旧规则保持有效。 |
| BUG-03 | P1 | 同一订阅保留已撤销历史绑定，远端复用相同入站 ID 后又创建活跃绑定。采样通过 ID 查找到第一条历史记录，把新用量写回历史记录，可能重复计费并更新错误的撤销状态。 | 当前扫描持有确切的活跃绑定引用，不再按重复 ID 重新选择第一条。回归确认历史计数不变，活跃绑定正确计费与撤销。 |
| BUG-04 | P2 | 已删除或外部已删除的入站，再次调用删除；部分面板返回不存在，导致重试流程报错。 | 删除前读取现有入站；已不存在时跳过面板删除，仍允许清理关联路由和限速，实现幂等重试。 |
| BUG-05 | P2 | 同时修改倍率、启用强制计量并提交负数总额度。接口最后才拒绝非法额度，之前已经采样旧用量或执行远端计量初始化。 | 将额度、到期、强制开关、倍率的校验提取为共同预检，网络操作前完成。回归确认非法请求不采样、不建立计量规则、不修改已用量。 |
| BUG-06 | P2 | 请求 Content-Length 为负数，原逻辑执行 `read(-1)`；持久连接可能一直等到对端关闭，占用处理线程。 | 读取请求体前要求 Content-Length 只包含非负整数字符，并保留体积上限。回归确认负数在任何读取发生前被拒绝。 |
| BUG-07 | P2 | 提交 JSON 数组、null、数字或字符串。请求体解析允许其通过，业务层出现 `.get` 等属性错误，错误提示不一致。 | 统一要求请求 JSON 为对象，提前返回明确错误；数组、null、数字、字符串全部有回归用例。 |

所有问题均先增加失败用例，再修改代码。原始失败输出、修复后输出见 `docs/testing/2026-10-23/`；精确回归用例见 [test_workflow_regressions.py](../tests/test_workflow_regressions.py)。

## 性能与可靠性优化

**OPT-01：移除面板计量的无效 SSH 会话。** 3x-ui / X-ui / X-Panel 本身提供计数，原 `ensure_meter` 仍先执行 SSH 连接及面板接入，随后立即返回。现在先检查登记类型，面板类型无需建立这次会话；独立 Xray / sing-box 仍执行真实计量初始化。回归确认该路径的连接次数从 1 次降为 0 次。实际节省时间取决于生产 SSH 延迟，未声称线上提速百分比。

另外，非法额度请求提前退出，减少无效远端操作；删除支持幂等重试，避免重复调用面板删除接口。

本机 1000 节点、10000 规则、30 次采样基准：

| 操作 | 中位数 | P95 | 说明 |
| --- | --- | --- | --- |
| 已缓存配置快照序列化 | 0.201 ms | 0.276 ms | JSON 1864863 字节，gzip 104825 字节；不包含网络传输 |
| 修改节点端口 | 30.45 ms | 42.21 ms | 包含备份和原子文件替换；不包含远端 SSH / 内核重启 |

这些值用于复现当前本地开销，不能与不同负载环境的旧结果直接计算提升比例。无需为本批问题改写后端语言。

## 未覆盖和保留限制

- 未连接生产服务器，未执行生产安装 / 升级、证书签发、真实 X-ui / X-Panel 账号接入及公网测速；当前环境未配置生产凭据。
- 未在真实 v2rayN / v2rayNG / Shadowrocket App 上进行设备验收。各版本的显示、导入与后台切换效果仍需实机测试。
- 服务器节点限速按独占入站端口执行，共用入站内按单个用户限速尚未实现。
- nftables 使用超速丢包、允许短时突发，不能当作平滑整形；UDP / QUIC 的真实代理吞吐与稳定性尚需实测。
- 到期与额度撤销依赖后台轮询和远端可达性；离线服务器不能保证立即删除节点。用量短时超出额度并非已消除的可能性。
- 外部工具删除节点、清空 nftables 规则或修改端口后，需要核对总控关联与限速状态；此批没有新增对所有外部变化的自动修复。

## 复现命令

基础检查：

```bash
.venv/bin/python -m unittest discover -s tests -q
NODE_PATH=/path/to/node_modules node tests/ui_smoke.cjs
NODE_PATH=/path/to/node_modules node tests/ui_visual.cjs
bash -n install.sh
```

完整检查需要本机安装 Chromium、Node.js 的 jsdom / puppeteer-core、Xray / sing-box / Mihomo 可执行文件，以及支持 `unshare -Urn` 的 Linux。设置 `MXIOC_XRAY_BIN`、`MXIOC_SING_BOX_BIN`、`MXIOC_MIHOMO_BIN`、`MXIOC_NFT_BIN`、`MXIOC_BROWSER_TEST=1` 和 `NODE_PATH`，再执行上述 Python 测试命令。缺少相应环境变量时，可选测试会明确显示 skipped。测试使用临时数据，请勿将临时测试入口暴露公网。
